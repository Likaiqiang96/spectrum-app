# 流光溢彩 + 滑动灵敏度修复 · 2026-10-17

## 1. 新颜色效果「流光溢彩」

颜色菜单第 4 档（原「彩虹」）升级为用户描述的**流光溢彩**：
**从低频到高频按彩虹色缓慢滚动**。

| 项 | 值 |
|---|---|
| 色相 | 完整 360° 横跨频谱（低频一端 → 高频另一端） |
| 饱和度/明度 | S=0.88 / V=1.0（比纯饱和更亮、更「溢彩」） |
| 滚动速度 | **320 px/s**（约 6 秒滚完一圈），方向 **低频 → 高频（左→右）** |
| 渐变结构 | **一个周期 = 频谱宽度 + `TileMode.REPEAT`**（关键，见下） |
| 额外柔光 | 一道 18% 宽的高光带每 3.5 秒扫过一遍（"流光"） |

> 第一版设的 85 px/s（22 秒一圈），用户反馈**「并没有流动起来」**——平滑彩虹没有可追踪的硬特征，
> 太慢在观感上等同静止；已加快到 420 px/s。
### 关键 bug：低频端被"钉死"成红色（用户反馈「低频不会体现绿蓝紫」）

第一版渐变铺的是「两倍频谱宽 + 两圈色相 + `CLAMP`」。平移往右推之后，窗口**左侧的采样点跑到
渐变范围之外**，被 `CLAMP` 夹成第一个色标 → **低频端永远是红色**，只有中高频在动。

改成 **「一圈宽度 + `TileMode.REPEAT`」** 后任意平移都无缝平铺。实测低频端（x=250）色相随时间：

```
77° → 308° → 177° → 47° → 274°     （黄绿 → 品红 → 青 → 橙红 → 紫）
```

即低频端现在会完整循环所有颜色。

> 另外顺手删掉了屏幕中间那条白色短横杠：它是**歌词占位符**（参考图里"没歌词"时的那一横），
> 歌词功能还没做，留着只会让人以为屏幕有问题。

**滚动方向验证**（录屏抽帧 + 直接追踪"红色带"中心 x）：

```
rb_002: 618 px → rb_004: 625 → rb_006: 634 → rb_008: 642 → rb_010: 650
```

单调递增 → 确认是**向高频方向流动**。

### 性能坑（已修）

第一版「流光」用 `clipPath(areaPath)` 把高光裁剪进频谱区域 —— 硬件层上复杂路径裁剪非常贵：
**渲染 16.1 ms、帧率掉到 49 fps**。
改成**对每根柱子按其到光带的相对位置算 alpha**（`sin(πu)` 剖面）再叠一个白色圆角矩形，
不用任何裁剪：**5.5 ms / 60 fps**（默认青红档 1.5 ms）。

## 2. 亮度和增益滑动"非常不灵敏" —— 根因是累加写错

```java
// ❌ 原来：每次 MOVE 都在同一个基准上覆盖，只有最后一小段位移生效
brightness = touchStartValue + step;
settings.setGainDb(touchStartValue + step * 48f);

// ✅ 现在：在当前值上累加本帧增量
brightness = brightness + step;
settings.setGainDb(settings.gainDb + step * 48f);
```

另外拖动期间**每帧写一次 SharedPreferences** 也会卡，改成 `setGainDb()` 只改内存、
抬手 `persistGain()` 落盘。起始判定阈值也从 3.5% 屏高降到 2%。

**实测（200 px 滑动）**：

| 操作 | 修复前 | 修复后 |
|---|---|---|
| 右侧上下滑 200 px | ≈ ±1 dB | **+12.8 dB**（再滑一次累加到 +24 上限） |
| 左侧上下滑 200 px | ≈ ±1.5% | **60% → 88%**（+28%） |

## 复现

```bash
adb shell am start -n com.spectrum.app/.MainActivity
adb shell input swipe 1900 700 1900 500 600   # 右侧上滑：增益 +12.8 dB
adb shell input swipe  300 700  300 500 600   # 左侧上滑：亮度 +28%

```
