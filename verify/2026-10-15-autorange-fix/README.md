# 自动量程修复：音源模式"每个频段都接近饱和" · 2026-10-15

用户反馈：**实际使用时每个频段都接近饱和**。查下来是**三个 bug 叠加**，全都与自动量程有关。

## 三个根因

### ① 限速算错（影响最大）

设计文档 §6.7 写的是"P95 按 ±6 dB/s 限速平移"。实现里：

```java
maxStep = 6f * dtMs / 1000f;     // dtMs 是单帧的 16 ms
```

但这段代码**每 8 帧（每 8 次分析帧）才执行一次**，于是实际速率变成
`6 × 0.016 = 0.096 dB / 0.4 s = 0.24 dB/s` —— **比设计值慢 25 倍**。

后果：P95 永远追不上真实电平，`floor = P95 − span` 一直偏低，
所有柱子都落在窗口顶部 → 整屏贴顶。

**修**：累积"距上次真正更新"的时长，用它算限速（`accMs`）。

### ② 显示窗口固定 32 dB

音源路是 8-bit 量化，动态范围被压缩；固定窗口下，分布窄的信号会整片挤在 P95 附近。

**修**：窗口改成跟着信号自身分布走 —— `span = clamp(P95 − P10, 22, 60) dB`，
即 P95 映射到 0.9、P10 映射到 0。窄动态范围信号会被"张开"成有形状的谱，
宽动态范围信号（真实的音乐）仍然占满整个高度。

### ③ +30 dB 电平补偿加错了地方

音源路的全局混音捕获天生比轨道级低约 34 dB，我加了 `MIX_GAIN_DB = 30` 补偿。
但它被加到了**频带值**上，而自动量程的直方图把 dB 夹在 `[−100, 0]` ——
于是所有响的频带都超过 0 dBFS、**全部堆在 0 dB 那一格**，P95 被顶到天花板，进一步加剧饱和。

**修**：补偿只加在 **VU 表的 RMS**（绝对刻度需要）上；频带值保持原始 dB，
交给自动量程做相对映射。

## 怎么在没有声音的情况下验证映射

新增了一个 **假频谱源**（`core/FakeProvider`，只有 `--ez fakespectrum true` 时启用）：
它不碰任何音频硬件，直接合成一段"像音乐一样"的频带 dB（低频最高、按 −4.5 dB/oct 滚降、
叠一个中频峰、每 1.2 秒一个鼓点），以 20 fps 往下发。
这样就能干净地单独检验渲染层的映射，不受 8-bit 量化底噪和真实音频的干扰。

## 复现

```bash
adb shell am start -n com.spectrum.app/.MainActivity --ez fakespectrum true  # 假频谱，验证映射
adb shell am start -n com.spectrum.app/.MainActivity --ez mixtest true       # 音源 + 听不见的测试音
adb shell logcat -s Spectrum:I      # 状态行里有 floor / p95 / span / p10，可直接看量程
```
