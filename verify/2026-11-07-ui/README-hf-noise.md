# 音源模式高增益下"高频反而更高"的原因与修复 · 2026-11-07

用户：**「使用内部音频的时候，我把增益调得很高，没有声音时频谱的高频还是有很高的值，
并且频率越高值越高，是什么原因？」**

## 原因：+3 dB/oct 的倾斜补偿把底噪"抬"成了假频谱

分带表里给每个频带乘了一个倾斜系数（为了让音乐的谱形看起来平衡）：

```java
tilt[k] = Math.pow(centerHz[k] / 1000.0, 0.5);     // 换算成 dB 正好 +3.01 dB/oct
```

累计抬升量（相对 60 Hz）：

| 中心频率 | 100 Hz | 1 kHz | 4 kHz | 16 kHz |
|---|---|---|---|---|
| 倾斜补偿 | +2.2 dB | +10 dB | +16 dB | **+24.3 dB** |

而系统混音捕获是 **8-bit 量化**（LSB 噪声大约在 −48 dBFS 量级），另外音频链路本身也有抖动。
这些残余噪声本来是**平的**，经过倾斜补偿后就变成**越往高频抬得越高**的斜坡；
增益开到 +24 dB 时，这个斜坡被整体抬进可见范围 —— 屏幕上就是"没声音，但高频很高、而且越高越亮"。

> 补充：麦克风路也有同样的倾斜补偿，但那抬的是**真实的环境噪声**（房间底噪本来就偏低频），
> 观感上不会这么假；音源路抬的是**数字量化噪声**，所以特别明显。

## 修复：两道闸

1. **底噪门限**（`SystemMixProvider.MIX_NOISE_GATE_DB = -42 dBFS`）：
   整体 RMS 低于这个门限就按静音处理，频带直接清零（−160 dB）。
   8-bit 的 LSB 噪声约 −48 dBFS，正好落在门限以下；而正常播放的音乐远高于它，不受影响。
2. **倾斜补偿封顶 +15 dB**（`BandMapper`）：`tilt = min(5.62, pow(f/1000, 0.5))`，
   16 kHz 处从 +24 dB 收到 +15 dB，斜坡变缓，即使有残余噪声也不会那么夸张。

## 实测

| 场景 | 门限前 | 门限后 |
|---|---|---|
| 音源 + 最大音量 + 增益+24 + 静音 | 全 0（rms −180dB）本来就无信号 | 仍全 0 |
| 音源 + 测试音 + 增益+24 | rms −3.4 dB → 正常显示 | **不受影响**（远高于 −42 dB 门限）|

> 说明：这台机器在"完全没播放"时捕获到的是**数字全 0**（rms −180dB），所以我在本地复现不出
> 用户看到的那个斜坡；但倾斜补偿的 24 dB 抬升是确定的，只要有残余噪声（别的 App 在输出静音流/
> 系统音效/抖动）就会显示成那个样子。两道闸都是针对这个成因下的。
