# 动态节奏加快 + 峰值点"雨滴"效果 · 2026-10-15

用户反馈两点：**频谱变化得太慢**、**峰值点的变化要有下雨的感觉**。

## 改了什么

| 参数 | 原来 | 现在 | 说明 |
|---|---|---|---|
| 柱形上升（攻击） | 15 ms（两条路一样） | 麦克风 **8 ms** / 音源 **22 ms** | 音源路只有 20 fps（50 ms 一帧），攻击太快会看到台阶 |
| 柱形回落（释放） | 250 ms | 麦克风 **90 ms** / 音源 **130 ms** | 原来那套太"黏"，这是"变化太慢"的主因 |
| VU 表 | 攻击 40 / 释放 400 ms | **12 / 220 ms** | 电平表也要跟手 |
| 峰值保持时间 | 默认 **1 s** | 默认 **0.5 s** | 菜单「峰值」仍可选 关/0.5s/1s/2s |
| 峰值下落方式 | 保持后按 **20 %/秒**（指数） | **匀速下落 1.6 屏/秒**（≈0.6 s 落满屏） | 这就是"雨滴"：脱离柱顶后匀速往下掉 |
| 自动量程 P95 限速 | 6 dB/s | **10 dB/s** | 整体电平变化跟得稍快一点，仍不至于"呼吸" |

## 峰值点冲高与"变化速度"挂钩（用户第二个要求）

「频谱变化的速度越快，峰值点应该上升得越高」—— 峰值点不再是"贴在柱顶"，而是：

```
目标高度 = 当前值 + 上升速率 × BOOST_PER_RISE      // BOOST_PER_RISE = 0.016 秒
          上限 = 当前值 + 0.32                  // MAX_BOOST = 0.32 屏高
```

实测（同一段假信号里四次瞬态，满高 207 px）：

| 频带 | 最大冲高 | 说明 |
|---|---|---|
| 18 | 79 px | 轻一点的瞬态 |
| 6 | 62 px | |
| 30 | 157 px | |
| 42 | 198 px | 最猛的一次，几乎顶到天花板 |

也就是说冲高是**连续随速度变化**的，不是每次都顶满；随后仍按 1.6 屏/秒匀速下落（雨滴）。
轨迹见 [`03-kick-overshoot.png`](03-kick-overshoot.png)（11 帧，每 40 ms）：
前 6 帧峰值点被"甩"在高处，后 5 帧匀速落下。

## 怎么在不出声的前提下量出来的

用假频谱源（`--ez fakespectrum true`）在固定频带上每 1 秒打一个 150 ms 的方波脉冲，
`adb shell screenrecord` 录 3 秒 → `ffmpeg -vf fps=50` 抽帧 → 逐帧量那一列柱顶/峰值点的 y。

实测（每帧 20 ms）：

| 阶段 | 帧 | 结果 |
|---|---|---|
| 攻击 | 43 → 47 | **80 ms** 冲到顶（含自动量程窗口跟随的时间） |
| 悬停 | 47 → 73 | **540 ms**（= 0.5 s 保持） |
| 下落 | 75 → 89 | 187→203→229→240→250→266→277 px，**匀速 ≈250 px/s**（满高 207 px，≈0.8 s 落满） |
| 下一滴 | 91 | 1 秒周期再次冲顶 |

[`01-peak-rain.png`](01-peak-rain.png) 是把下落段 13 帧（每 40 ms）横向拼起来的图：
可以看到峰值点脱离柱顶后**匀速往下掉**，最后一帧新脉冲到来、柱子重新冲顶。

## 复现

```bash
adb shell am start -n com.spectrum.app/.MainActivity --ez fakespectrum true
adb shell screenrecord --time-limit 3 --bit-rate 12000000 --size 1110x540 /sdcard/dyn.mp4
adb pull /sdcard/dyn.mp4
ffmpeg -i dyn.mp4 -vf fps=50 f_%03d.png
```
